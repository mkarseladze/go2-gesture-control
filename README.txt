რას აკეთებს ეს ვერსია
კამერიდან ამოიცნობს ხელს და შესაძლო ბრძანებებს ეკრანზე აჩვენებს.
ამ პაკეტში რობოტთან დაკავშირებისა და რობოტის მოძრაობის კოდი არ შედის.
აქ ნაჩვენები STOP ეკრანის მდგომარეობაა და რობოტის ავარიული გაჩერება არ არის.

პირველი ნაბიჯი — კომპიუტერის შემოწმება
1. გადაიტანეთ ZIP პროექტის Ubuntu კომპიუტერზე და სრულად ამოიღეთ ფაილები.
2. გახსენით მიღებული go2-gesture-starter საქაღალდე.
3. საქაღალდეში ცარიელ ადგილას მარჯვენა ღილაკით აირჩიეთ Open in Terminal.
4. გაუშვით:
   python3 doctor.py
5. მიღებული შედეგი გამოგზავნეთ ჩატში. ეს ნაბიჯი კამერას არ რთავს.
   ანგარიშში ჩანს Unitree SDK2-ისა და RealSense-ის Python მოდულების
   ხელმისაწვდომობაც, თუმცა მათ არსებობას რობოტთან გამართული კავშირი არ ადასტურებს.

Ubuntu-ის ავტომატური მომზადება

ტესტებსა და მოდელის შემოწმებას. კამერას და რობოტს არ უკავშირდება.
გაუშვით ჩვეულებრივი Ubuntu ანგარიშით; სისტემური პაკეტებისთვის მხოლოდ
python3-venv შეიძლება დაგჭირდეთ: sudo apt install python3-venv

თუ პაკეტი უკვე Ubuntu-ში გაქვთ ამოღებული, მის საქაღალდეში გაუშვით:

და მათ ავტომატურად არ გადაწერს. სხვა საქაღალდის ასარჩევად გამოიყენეთ
--destination პარამეტრი.

დაყენება — კომპიუტერის ვერსიის დაზუსტების შემდეგ
საჭიროა ჩვეულებრივი Ubuntu სამუშაო მაგიდა, კამერა და ინტერნეტი პაკეტების დასაყენებლად.

თუ venv ან pip აკლია, Ubuntu-ზე შეიძლება დაგჭირდეთ:

თუ pip-ს თავსებადი პაკეტი ვერ უპოვია, საჭიროა Python/Ubuntu/არქიტექტურის შემოწმება.

პროგრამის შემოწმება კამერის გარეშე:
   python -m unittest -v
   python app.py --self-check

კამერის გაშვება:
   python app.py

შემდეგ ჯერზე ჯერ კვლავ გაააქტიურეთ გარემო: source .venv/bin/activate
პროგრამაში კლავიშების გამოსაყენებლად კამერის ფანჯარა უნდა იყოს აქტიური.

ეკრანი და კლავიშები
Raw: უშუალოდ ამოცნობილი ჟესტი.
COMMAND: გაფილტრული ბრძანება, რომელიც ეკრანზე გამოსატანად მივიღეთ.
PLAN ONLY: შესაბამისი SDK მოთხოვნის ტექსტი; პროგრამა ამ მეთოდებს არ იძახებს.
Move-ის პარამეტრების რიგია წინ/უკან სიჩქარე, გვერდითი სიჩქარე, მობრუნების სიჩქარე.
საცდელი განაწილება: FORWARD -> Move(0.15, 0, 0); BACKWARD -> Move(-0.15, 0, 0);
LEFT -> Move(0, 0, 0.30); RIGHT -> Move(0, 0, -0.30); STOP -> StopMove().
რიცხვები მოთხოვნილი სიჩქარეებია (მ/წმ და რად/წმ), რეალური გაზომვა არ შესრულებულა.
რეალურ Go2-ზე მობრუნების მიმართულება ცალკე უნდა შემოწმდეს დაბალი სიჩქარით.
ეს მოთხოვნების ჩვენებაა; რეალური რობოტის ან მისი ფიზიკის სიმულაცია არ არის.
მაგალითების ნახვა კამერის გარეშე: python3 motion_plan.py

განახლება უკვე მომზადებულ Ubuntu-ში, კამერის პროგრამის დახურვის შემდეგ:
   sudo -u "$USER" -g vboxsf python3 /media/sf_Go2Project/prepare_ubuntu.py --copy-only
ამ რეჟიმში პაკეტები თავიდან არ ყენდება და არსებული .venv ნარჩუნდება.

პროგრამა თავიდან DISABLED მდგომარეობაშია და COMMAND ყოველთვის STOP იქნება.
A: ეკრანზე მოძრაობის ბრძანებების ჩვენების ჩართვა/გამორთვა.
SPACE: ამ ჩვენების გამორთვა.
ESC ან Q: პროგრამის დასრულება.
ეს კლავიშები რობოტის პულტს არ ცვლის.

როგორ აჩვენოთ ჟესტები
კამერას უჩვენეთ მხოლოდ ერთი ხელი, ხელისგული კამერისკენ, თითები ზემოთ.
მთელი ხელი კადრში უნდა ჩანდეს. გამოიყენეთ კარგი განათება.
მოძრაობის ჟესტი დაახლოებით ნახევარი წამით გააჩერეთ.

FORWARD: გაშლილია საჩვენებელი თითი; შუა, არათითი და ნეკა მოკეცილია.
BACKWARD: გაშლილია საჩვენებელი და შუა; არათითი და ნეკა მოკეცილია.
LEFT: გაშლილია საჩვენებელი, შუა და არათითი; ნეკა მოკეცილია.
RIGHT: გაშლილია ოთხივე თითი; ცერი კარგად მიიკეცეთ ხელისგულზე.
STOP: ოთხი თითიც და ცერიც სრულად გაშალეთ.
UNKNOWN: გაურკვეველი ჟესტი; COMMAND დაუყოვნებლივ ხდება STOP.
ორი ხელის დანახვისას ან ხელის დაკარგვისას COMMAND ასევე STOP ხდება.

თუ RIGHT და გაშლილი ხელისგული ერევა, დატოვეთ STOP და გვაცნობეთ.
ზღვრები ჯერ თქვენს ხელებზე, კამერასა და განათებაზე უნდა შემოწმდეს.
ეს არის წერტილებზე დაფუძნებული საცდელი წესები; ყველა პოზაში ამოცნობა გარანტირებული არ არის.
ეკრანზე ინგლისური მოკლე სახელებია; ზემოთ მოცემულია მათი ქართული მნიშვნელობები.

headless OpenCV ამ პროგრამისთვის არ გამოდგება, რადგან ეკრანის ფანჯარა გვჭირდება.

დღე 1-ის მისაღები შედეგი
- ოთხივე მონაწილე ხსნის პროგრამას და ასახელებს Raw და COMMAND-ის განსხვავებას.
- ხუთივე ჟესტი თითოეულ მონაწილეზე 10-ჯერ შეამოწმეთ; ჩაწერეთ შეცდომები.
- შეამოწმეთ ხელის დაკარგვა, ორი ხელი და გაურკვეველი ჟესტი: COMMAND უნდა გახდეს STOP.
- შეამოწმეთ DISABLED მდგომარეობა: მოძრაობის ბრძანება არ უნდა გამოჩნდეს.
- დაწერეთ განათება, მანძილი და პირობები, რომლებშიც ამოცნობა მუშაობს.

ერთი კვირის სამუშაო განაწილება
დღე 1: Ubuntu-ის შემოწმება, დაყენება, კამერა.
დღე 2: ჟესტების ცდა ოთხივე მონაწილეზე, პრობლემების გასწორება.
დღე 3: პასუხისმგებელ თანამშრომელთან Go2 EDU-ის SDK-ისა და ქსელის შემოწმება;
        ჯერ მხოლოდ რობოტის მდგომარეობის წაკითხვა.
დღე 4: ცალკე მართვის პროგრამით ნელი მოძრაობისა და გაჩერების შემოწმება.
დღე 5: კამერის პროგრამისა და მართვის პროგრამის გაერთიანება.
დღე 6: სრული ცდები და მოკლე სარეზერვო ვიდეო.
დღე 7: პრეზენტაცია და რეპეტიცია; ახალი ფუნქციების დამატება აღარ დაგეგმოთ.
თუ რობოტთან წვდომა ან კავშირი აგვიანებს, კამერის დემო დამოუკიდებლად მაინც მუშავდება;
რეალური რობოტის დემოს დასრულება ჯერ დადასტურებული არ არის.

ოთხი მონაწილის საწყისი როლები
1. კომპიუტერი და კამერა: გაშვება, გარემო, შეცდომების შეგროვება.
2. ჟესტები და ტესტები: ცდების ცხრილი, არასწორი ამოცნობის აღრიცხვა.
3. რობოტი და კავშირი: პასუხისმგებელ თანამშრომელთან ერთად SDK/ქსელი/პულტი.
4. ახსნა და პრეზენტაცია: სქემა, მუშაობის აღწერა, დემოს სცენარი და ვიდეო.
ყველამ უნდა შეძლოს სისტემის საერთო პრინციპისა და საკუთარი ნაწილის ახსნა.

რობოტთან დაკავშირების მომდევნო ეტაპი
საჭირო იქნება Go2 EDU-ის firmware/SDK-ის ვერსია, კომპიუტერის ქსელის ინტერფეისი,
პულტით გაჩერების პრაქტიკული შემოწმება და თავისუფალი საცდელი სივრცე.
საბოლოო მართვას ცალკე მოუწევს ახალი კადრების კონტროლი და ბრძანებების ვადის შემოწმება,
რათა კამერის ან ამოცნობის გაჭედვამ ბოლო მოძრაობის ბრძანება აქტიურად არ დატოვოს.
ამ პაკეტის CommandGate დამოუკიდებელი watchdog არ არის; მისი პირდაპირ
რობოტის მართვად გამოყენება ამ შემოწმებების გარეშე არ შეიძლება.
